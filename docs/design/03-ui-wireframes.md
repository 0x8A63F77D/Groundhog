# 03 — UI 线框（Avalonia，MVVM）

> 文字线框只定**结构与信息层级**；间距、字重、颜色、图标是视觉保真问题，按方法论 §五.5 留给 Owner 眼球裁决——里程碑 4 交一版截图，不自主迭代。
> 每个页面的每个可配置项都遵守：左列 **当前会话（只读）**，右列 **下次启动（可编辑）**，两者不同 → 右列项带 `⟳ 重启后生效` 徽章。

## 1. 窗口骨架

```
┌──────────────────────────────────────────────────────────────────────┐
│ Groundhog        [UWF 当前：已启用 ●]  [下次启动：已禁用 ⟳]  [↻ 刷新] [自动刷新 ✓] │
├──────────┬───────────────────────────────────────────────────────────┤
│ 总览      │                                                          │
│ 卷        │              页面内容（见 §3–§7）                          │
│ 注册表    │                                                          │
│ Overlay   │                                                          │
│ Servicing │                                                          │
│ 待重启 (3)│                                                          │
├──────────┴───────────────────────────────────────────────────────────┤
│ 操作日志                                                     [清空]  │
│ 12:03:14  已提交：卷 C: 新增排除 \Logs；重启后生效                    │
│ 12:03:09  读取 UWF_Overlay.AvailableSpace 失败（0x80041013）；显示为不可用 │
└──────────────────────────────────────────────────────────────────────┘
```

- 顶栏两枚状态胶囊直接来自 `FilterState`；`Unavailable` 时显示"未知"，不显示开/关。
- 读失败的两种呈现（都由 `LastReadFailure` 派生，02 §3.1）：
  - 已有快照 → 顶栏刷新按钮旁出现"数据可能过时（上次刷新失败，见日志）"横幅；成功刷新后消失。
  - 尚无快照（探测成功但首次读失败）→ 页面内容区整体替换为空态面板："无法读取 UWF 状态：<摘要>  [重试]"，重试 = `RefreshRequested(Manual)`；导航与日志区照常可用。这与引导页（§2）不同：UWF 存在，只是这一次读失败了。
- 左侧导航"待重启 (n)"的 n = `Diff(snapshot).Count`；n=0 时不显示计数。
- 日志区常驻，可折叠。

## 2. 引导页（错误级别 a / b）——替代整个主界面

```
┌──────────────────────────────────────────────┐
│  ⓘ 此系统未安装 Unified Write Filter 功能      │
│                                              │
│  Groundhog 通过 WMI 命名空间                   │
│  root\standardcimv2\embedded 访问 UWF，       │
│  当前系统上找不到该命名空间/类。                │
│                                              │
│  技术细节 ▸ <探测异常原文>                     │
│                                              │
│  [重新检测]                                   │
└──────────────────────────────────────────────┘
```
- (a) 未安装：文案如上；(b) 权限不足："请以管理员身份运行"（manifest 已 `requireAdministrator`，此页只在 UAC 被绕过等边角出现）；`QueryFailed`："无法查询 UWF 状态"+ 重试。
- 三者文案不同，但都由 `UwfAvailability` 的类型决定，不看字符串。

## 3. 总览页

```
 当前会话                          │ 下次启动
 UWF 保护       已启用 ●           │ 已启用 ●
 Overlay 类型   RAM                │ Disk   ⟳ 重启后生效
 Overlay 上限   1024 MB            │ 4096 MB ⟳ 重启后生效
 Servicing      关闭               │ 关闭
 HORM           不可用（此系统不暴露） │  —                     ← [待 VM 确认]

 Overlay 使用（实时）
 ├────────────────┼──────────┼──────────────────────────┤
 0        已用 812 MB   警告 900   严重 1000     可用 212 MB   合计 1024 MB
 [启用 UWF] [禁用 UWF…] [安全重启…] [安全关机…]        （… = 需二次确认）
```
- 分段条：分母 = 已用 + 可用（裁决 D6）；两条阈值线按值定位；已用段颜色按 `<警告 / ≥警告 / ≥严重` 三档（具体色值留 Owner）。任一相关字段 `Unavailable` → 整条隐藏，原位显示"Overlay 使用情况不可用（原因见日志）"，**其余页面不受影响**。
- "合计 1024 MB"旁若 `OverlayConfig.Current.MaximumSizeMb` 与分母不等，附小字"配置上限 N MB"——只展示，不裁决。

## 4. 卷页

```
 卷      当前：绑定方式   下次：绑定方式   当前会话：保护   下次启动：保护     CommitPending
 C:      按盘符           按盘符 ▾         受保护 ●         不受保护 ○ ⟳       否
 D:      按卷名           按卷名 ▾         不受保护         不受保护            否
   \\?\Volume{...}\                                                                        (卷名可展开显示)

 ── 卷 C: 的文件排除 ──────────────────────────────────────
 当前会话                     │ 下次启动
 \Logs                        │ \Logs
 \Users\Public\Cache          │ \Users\Public\Cache
                              │ \Temp                ⟳ 重启后新增
 \Old                         │                      ⟳ 重启后移除
                              │ [+ 添加排除路径]  [− 移除所选]
 ── 提交（立即写穿到底层卷，不可撤销）───────────────────
 路径 [\path\to\file        ]  [提交文件…]  [提交删除…]
```
- "当前：绑定方式"列只读，来自 `VolumePair.Current.BindByDriveLetter`；保护开关、绑定方式的下拉都只作用于**下次启动**列（provider 只写 next 实例，裁决 D3），两列不同时下次启动列带 `⟳`（与其它可配置项同构，见 00 §UI 规则；`VolumeBinding` 本已是 02 §1 的一个 `PendingArea`）。
- 排除列表按集合差渲染增/删徽章（02 §1）。
- 输入框校验用 02 §2 的纯函数，错误就地提示；WMI 返回的 HRESULT 走失败详情弹窗。

## 5. 注册表页

与卷页同构：上半部 `PersistDomainSecretKey` / `PersistTSCAL` 两个开关（当前/下次并排），下半部排除键列表 + 提交注册表键/值。

## 6. Overlay 页

```
 当前会话                          │ 下次启动
 类型      RAM                     │ ( ) RAM  (•) Disk   ⟳
 上限      1024 MB                 │ [4096   ] MB        ⟳
   ⚠ 修改类型/上限要求"当前会话 UWF 已禁用"（来自官方文档）。当前会话：已启用 → 控件禁用并显示此提示。

 阈值（全局，实时）
 警告   [ 900 ] MB      严重 [ 1000 ] MB     [应用]        （一个命令：SetOverlayThresholds(w, c)，两次 WMI 调用的顺序在 provider 内部处理）
```
- 前置条件提示由 `FilterState.CurrentEnabled` 驱动；`Unavailable` 时不禁用控件（不因读失败夺走操作），只显示"无法确认前置条件"。

## 7. Servicing 页

两列开关 + 一句说明（"servicing 模式下重启后 UWF 临时不过滤，用于装更新"——文案来自文档，不加自己的解释）。`UpdateWindows` 不做。

## 8. 待重启汇总页

```
 以下 3 项将在下次重启后生效：
 • UWF 保护：已启用 → 已禁用
 • Overlay 类型：RAM → Disk
 • 卷 C: 排除：新增 \Temp
 [立即安全重启…]                        （二次确认后调 RestartSystem，D7）
```
列表就是 `Diff(snapshot)` 的渲染，每行 `PendingChange` 一条，文案模板按 `PendingArea` 查表。

## 9. 失败详情弹窗（错误级别 d）

```
 操作失败：设置 Overlay 类型
 类/方法：UWF_OverlayConfig.SetType
 HRESULT：0x80070005
 系统消息：拒绝访问。          （原文，可能是本地化文本）
 [复制详情] [关闭]
```
复合命令部分失败时（`CompletedSteps` 非空）多一段：
```
 已生效：SetWarningThreshold        ← 来自 CompletedSteps
 未生效：SetCriticalThreshold（上面的失败）
 提示：面板正在刷新到最新状态（命令完成后自动重读，`ShowFailureDetails` 与 `ReadSnapshot` 同时发出，读取是异步的，弹窗打开时面板可能还没更新，见 02 §3.4）。
```

## 10. 二次确认弹窗（危险操作）

文案模板按命令类型：说明**产品语言的后果**（"禁用后下次启动起系统改动将被永久写入磁盘"），确认按钮带命令名。集合在 02 §5，UI 不各自判断。

## 11. 语言与本地化

MVP 单语言（中文界面，brief 明确不做多语言）；所有用户可见字符串集中在一个资源类，但**没有任何逻辑读这些字符串**。系统消息原文（`SystemMessage`/`Detail`）只在详情/日志里原样展示。
